# Windows single-journey execution budget

This source input selects one of UI1, UI2, UI3 or UI4 per new c01 Windows run.
The frozen G1 journey and platform combinations remain the acceptance scope.
The journey's HTTP actions, SDK/PG birth evidence, complete107 facts and owned
cleanup are unchanged. Previous early source-context failure and the300s
truncated attempt retain their original labels and evidence.

`windows-ui-command-owner.cjs` is a static derivative of the reviewed c01
`command-owner.cjs`. It exports only `runOwnedCommand` and `stopOwned`. Its full
process birth identity, group scan, IPC handshake, signal and stop sections are
byte-identical to the mature original runtime. The shared300s runtime and the
API900s owner remain unchanged. Its command entry is only the current Linux
Node executable, the exact absolute c01 `windows-ui-runtime.mjs --worker`, one
journey and the same actual UUID in CLI and ownership run ID. The precreated
single-link regular0600 log is the exact c01 private
`ui-windows-owner-{backend}-{tag}.log`; parent components and0700 private modes
are checked. The ordinary original no-follow/inode checks remain in place.

The execution command deadline is1200000ms. The original startup/handshake
budget is separate and at most60000ms. The original stop grace and kill budgets
are separate. This does not claim a1200s total wall time including startup and
stop. The fixed runtime caller requests1200000ms; no arbitrary timeout CLI is
introduced. A deadline or a nonzero worker result remains failure and stops the
same owned process tree without retrying or constructing a business report.

The runtime starts a900000ms cooperative pipeline cancellation timer before
fixture preparation. It retains the same controller/signal and resource-finally
paths. On entry to the browser bridge it subtracts the actual preparation
interval. The bridge receives `min(840000,900000-elapsed)` milliseconds and the
driver receives `min(780000,bridge-60000)`. A remaining driver budget below1000ms
refuses to start a new browser. Thus the driver expires before the bridge; the
outer command leaves300s after the pipeline deadline for the existing closeout.
These are cancellation and fail-stop bounds, not an assertion that every future
attempt will finish or that cleanup is already proved.

The bridge still performs a real fresh Windows process inspection before every
callback and on profile/terminal/stop. It sends credentials/configuration after
the original identity ACK. The finite budget shape and values are recomputed
from the single journey and elapsed preparation in both bridge and driver.
The unprofiled bridge's original default300s and maximum360s are unchanged.
The existing20s cooperative abort,60s callback queue,60s original stdio retention
and20s identity-close budgets are unchanged. Driver EOF, callback failure,
retention failure, pending transactions or failed closeout retain their
existing partial/failure treatment; this input grants no adoption or cleanup
authority.

The owned worker receives only unchanged inherited `PATH`, `HOME`, `LANG`,
`WSLENV`, `WSL_INTEROP`, `DISPLAY`, `WAYLAND_DISPLAY` and `XDG_RUNTIME_DIR`.
The transport fields are the original bridge/native-owner allowlist; they
preserve the actual WSL Windows-interop path. The worker gets no ambient DB,
JWT or `NODE_OPTIONS`. The browser retains its existing separate Windows-system
environment allowlist. Raw environment values are not serialized by this
budget input.

Pure tests run the entire copied owner over Fake kernel/process/FS/IPC/clock
operations, including a command beyond900s, the1200001ms rejection, wrong
handshake/birth/entry/UUID/selection/environment, deadline and owned descendant
stop. Other tests exercise the production c01 bridge in memory through profile
ACK, two identity-checked callbacks, the shorter driver configuration and
terminal stop. No child process, PowerShell/CIM operation, private file, SQL,
HTTP connection or browser executes in these tests. Root must bind a new exact
source capsule and execute each actual journey; SourceReady alone grants no
actual Pass, G3 or G4.
