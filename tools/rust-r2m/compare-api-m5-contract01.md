`compare-api-m5-core.mjs` imports the c01 sibling `comparison-api-opaque.mjs` and `comparison-api-domain-clock.mjs`. It grants no ownership and receives actual values/keys only from Root. `m5Operation` maps finite original method/path combinations; it never retries another backend or converts unrelated routes into clock producers. `M5RootReader` is Root Linux only. It restricts reads to the exact new c01 private tree, backend/run journal and acceptance files, pinned controlled-peer plan/closeout, and the new public source store. It checks ordinary files, symlinks/hardlinks, inode identity, private modes and full raw byte SHA/size. Old M private paths, traversal and cross-backend/run references are rejected. The caller supplies only explicit existing refs; directory discovery is not a substitute for a missing proof. Journal namespace/marker/backend/run/database/source-head bind the c01 graph. A failed old M5 graph cannot become c01 evidence by a filename change.

Only Root invokes `readManagedKeys`. It uses the actual c01 `loadManagedEnvironment` at its fixed backend.env path. Actual values stay in memory and feed the finite cipher/state functions; only its separate `.receipt` may be serialized. No environment/key/plaintext/child stderr is placed in public output. The actual entry will preserve original read/validation errors in a new exclusive0600 c01 diagnostic rather than hiding their cause.

Ordinary authority verification precedes each pure proof: original intent/PK absence, SDK or PG outer COMMIT, independent visibility, typed parent/scope and immutable identity. A query/response ID is never an admission. The comparison-owned proof shape is A's reviewed `R2M-comparison-owned-row-proof`, with exact original owned object and creation-proof digest. Full-row/schema/version checks stay separate from opaque verification. Complete107 before/after/outside baseline and all known writes/cleanup must remain required in the actual adapter.

All actual response bytes/length/hash and parsed-entity equality remain strict. The actual adapter must also retain original request/state/code/cookie bytes and their existing evidence bindings. Frozen functional headers and explicit existing R1A addition remain observable; statuses/errors/entities cannot be normalized away. There is no generic64hex,8hex or `At$` rule.
