# R2M fixture contract — SourceReady candidate

Root owns provisioning, service/process owners, live SQL/HTTP and final admission. A owns the new tools listed here; B owns scenario descriptions and adapters. Imports and pure tests open no environment file, database, HTTP endpoint or container.

Fixed namespace `poms-r2m`; marker `1a6b458a-2e55-4dc9-8b50-0f1947a1a7d5`; databases `poms_r2m_nest` / `poms_r2m_rust`; role `poms_r2m_app`; host port `20432`; control schema `r2m_control`. `docs/design/rust-r2m/g1-environment-plan.json` is the environment authority. No old private path or ambient DB override is accepted.

## Entry and evidence interface

- `Fixture.open(backend, runId)` in `fixture.mjs`: explicit Root invocation only. New private journal directory `m-runs`; files `0600`, directory `0700`, no symlinks, atomic revision checks.
- `prepare({ viewerPermissions })`, `borrowSeedPrincipals()`, `borrowCanonicalDefinitions()`: Root only. The two seed principals and three definitions from G1 remain full-row readonly snapshots; none can be owned or deleted.
- `defineCase(caseId, { actors, projects, borrowedActors, borrowedDefinitions, anonymous, ownedCustomerIds, ownedLeadIds })`: actors/projects must already have creation proof. Case scopes and request identities are immutable. Additional named platform/provider scopes will be explicit fields, not arbitrary UUID adoption.
- `intent(table, immutableSelector, { caseId, expectedMax })`: before-observe exact selector; generated IDs are not authority. Default maximum is finite; absent/no-create outcomes must be resolved explicitly.
- `creationEnvelope(receipt)`, `registerNativeAuthority(receipt)`, `registerPgObserver(receipt)`, `recordCommittedCreates(rows)`, `adoptIntents()`: actual SDK `afterCreate` plus outer transaction commit or actual PG INSERT/outer-COMMIT observer, followed by independent visibility and immutable identity. A DTO, query match or synthetic receipt never grants ownership.
- `insert(table, values, { caseId })` / `insertPreparedBatch(plan, { caseId })`: exact planned PK absence, INSERT/RETURNING, xid/xmin, COMMIT ACK and independent visible row. Source-prepared facts retain that label; they are not Rust/Native business producer runs.
- `planSettingCreate('attachment.max-upload-size-mb', { caseId })` must observe the canonical registry key absent. `adoptSettingCreate(intentId, certificate)` requires a registered PG observer, exact `proof.table/key/insertedIdentity`, creation context, full xid/outer-COMMIT statuses and independent row visibility. An existing key refuses ownership. `resolveNoSettingCreate` handles proven absence. Arbitrary temporary keys are not API success cases because the original service rejects keys outside its registry.
- The unchanged migration initializes that canonical row. The selected R2M path therefore uses `admitBaselineSetting(admission,{caseId})`, `recordBaselineSettingAfter(requestReceipt)`, then `restoreBaselineSetting()` only after `drain()`. This is one named new-environment singleton lease, never ownership/delete. Admission binds Root's precise corrective checkpoint and C's exact-source review; the full initial row must be version1/integer50/null updater. Restore requires current full row equal to the recorded expected-after row, CAS of every original value/version/time/updater, real COMMIT and full-row equality from another newly validated connection. A changed row or uncertain COMMIT blocks cleanup of its owned actor references. One real lease scope can serve M2/UI logical steps; logical labels never widen the actual case/request identity.
- `updateOwned(table, id, values, reason)` / `directMutation(...)`: exact already owned identity only, journalled before/after and COMMIT outcome; immutable fields cannot change. Restore uses the same identity and original captured values.
- `facts({ caseId })`: actual complete owned rows and per-row hashes from an independent transaction, plus borrowed snapshot checks. This is not a DTO projection and must be kept private when rows contain credentials/ciphertext.
- `drain(receipt)` then `cleanup()`: Root supplies exact stopped writer identities and pending-transaction/active-work evidence for this run. No cleanup without that explicit receipt. All 107 tables are scanned for physical/logical references; only the named supported ownership table union can be deleted. Every DELETE must match exactly one proven row. Full readonly borrow checks, exact nullable cycle edges, first zero and independent second zero remain required; repeat cleanup produces zero matches/changes.
- `planObjectPrefix()` fixes a previously absent `poms-r2m/<runId>` local key prefix. `certifyLocalObject(table,id,key)` binds exact local bytes to an independently visible, creation-certified row. Object preflight rejects unregistered files and symlinks before database deletion; cleanup checks exact bytes, removes only certified keys and fresh empty directories, then checks zero again. Cloud-peer objects remain a separate Root owner receipt and are never claimed by this local ledger.
