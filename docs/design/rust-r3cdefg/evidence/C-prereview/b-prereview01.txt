## 冻结前需消歧的记录

### C-B-01：把 G1 前 Native 语义见证与 G3 候选验收分列

B报告137行要求先Native裁决全部 nativeWitnessRequired=true 再冻结G1，但同一矩阵把 B-DOWNSTREAM-01（真实Rust POST生产者）及候选Rust/UI比较也标为true。literal执行会形成先有产品才可G1的循环。

Root master应明确列出：G1前必须settle的Native事实，以及G2后/G3的Rust、双端HTTP、四组合UI、真实生产者消费链。G3项保留not-run，G1只冻结其输入/断言/证据要求，不提前伪造执行结果。无需改B原件；在master按case id消歧并保留其哈希即可。

### C-B-02：历史异常fixture不能突破受保护DDL

B-WORKSPACE-06标题包含null stored enum；原EX-27中status/bidMode/currentStage/decision/resultStatus/materialStatus/timelineStatus均NOT NULL。应拆成：原约束下允许的未知varchar值、nullable字段的null，以及被DB拒绝或不可构造的null enum。不能为HTTP读取场景drop约束或把不可构造状态记成功。

B-VERSION-06也应在原unique约束下验证可构造的current/status组合；不拆partial unique来制造同一project多current。原三列ORDER BY仍按源码保留，无法构造的并列排序不冒称运行验证。

### C-B-03：机器ownership排除http.rs

B矩阵authorScope写模块整目录；md/manifest已明确except http.rs且Root独占公共接线。Root master应以机器可判定的排除规则冻结，避免后续仅按authorScope glob审差异时把Root的http.rs归给作者。此项是记录消歧，不是已发生越权。

## 最小共享接口建议

沿用A/B候选接口，不扩充领域规则：

- project_bid_commercial::store::current(&mut PgConnection, project_id: &str) -> Result<Option<Row>, sqlx::Error>
- project_bid_commercial::store::by_id(&mut PgConnection, process_id: Uuid) -> Result<Option<Row>, sqlx::Error>
- project_bid_commercial::summary(&Row) -> serde_json::Value
- Service::new(Database)；list/workspace/create返回Result<projects::model::Wire, module Error>，各方法参数与Error到公共HTTP错误的转换仍须Root master冻结。

Row承载23字段的DB事实，文本状态用原字符串保留。current保留三个谓词/三列DESC；by-id保留无额外过滤的历史读取。它们不BEGIN/flush/lock/retry/鉴权/写审计/补项目状态检查。报价命令UUID字符串不得为了调用该DB接口先canonicalize；by-id的Uuid仅来自已存引用。

现有projects::store::find/user_names/org_names已公开，可作Root批准桥的底层；不复用较窄的projects::store::BidRow替代完整竞标Row。现有Wire::object只处理顶层原UTF16字符串，适合POST parent summary；DB读回与同请求原字符串仍分别处理，不把serde_json::Value当JS UTF16保真输入。

Root master还须明确module service如何接收actor/permissions及pending session flush事实；共享current/by-id不能隐藏这种写入。保留既有54ignored/schema/TZ/隔离例外的原标签。
