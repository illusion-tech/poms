# R2M 功能 UI 的受控无缓存输入

本记录保留原 G1 和 UI1 原始缓存运行。它固定同一功能验收的新浏览器输入，不宣称缓存协商或性能兼容；G3/G4 仍待实际验收与独立复核。

## 触发事实

`r2m-joint17` 的 Linux UI1 原生 `uin1d` 与 Rust `uir1d` 各完成四步、30 次真实代理 HTTP、完整 107 表事实及 owned 双零清理。两端存在 11 条真实的 Native 304 / Rust 200 响应差异。原请求、条件头、响应状态、空或非空实体及全部摘要保留，不能将这些响应直接归一为等价。

独立边界核查未发现 R1A、R1D 或 R2M 将 JSON ETag/If-None-Match/304 协商指定为冻结验收项。R2M 冻结功能旅程的真实状态与完整响应；K/J 的 binary `private, no-store`、HEAD、Range 和流边界仍须保留。

## 新输入与严格判据

四种 UI 组合统一在首次页面导航前、页面仍为 `about:blank` 时，通过该浏览器真实 CDP 会话启用 Network 并设置 `Network.setCacheDisabled(true)`，保留真实 ACK。会话随该 owned context 关闭。代理不删除、不改写原请求头，不 mock、不合成响应，不改变产品 API、守卫或 DOM。

真实代理继续保留原 `rawHeaders`、完整请求与响应字节，另对 `If-None-Match` 和 `If-Modified-Since` 逐名记录计数及摘要。新受控运行必须从实际请求证明这些条件头为零；CDP ACK 本身不足以证明输入符合要求。所有状态码、实体、权限结果、完整 107 表前后事实和清理要求继续严格比较。

新源包经独立 SourceReady 后捕获新 source epoch，重新运行受影响 UI 旅程。原 UI1 缓存运行保持“功能步骤已观察、缓存响应存在真实差异”的标签，不改为字节等价，不作为缓存兼容或性能结论。未冻结缓存协商不在本批另加为新产品能力。

本纠偏不新增公共操作，不改原 G1，不扩大 R3–R7 或真实云服务范围；#80/#67 只有完成全部本批条件后才能关闭，#57 保持开放。
