## 本批有效规则

1. **命令原子性。** Lead 状态/归属、评分、覆盖记录、必要快照和必要审计属于同一业务命令时使用同一事务。任一必要写入失败均回滚，禁止返回失败但状态已经提交。真实编号预留仍保持唯一性，失败可留跳号，不回收或重用号码。
2. **并发与状态转换。** 必须在写入时校验实际版本和合法状态；同一 pending 覆盖只能批准一次。并发失效方返回明确的 409，不把数据库乐观锁失败当普通 500，也不允许同一 expected version 双成功。替代旧批准和批准新记录、快照、审计整体提交。
3. **快照去重。** 比较规范化后的事实、闸口、公式、评分与评级。JSON 对象键顺序不是业务变化；仅改名称且评分事实不变，不制造评分历史。事实真实变化时仍按原评分设计记录。
4. **文本与输入。** 本批持久化文本拒绝 NUL 和孤立 surrogate，早期返回可理解的 400，避免落库 500 或 POST/GET 静默改变文本。合法 Unicode 按公开字符长度约束处理。非法数组只需明确拒绝，不复制 Zod 对错误对象追加的无意义长度 issue。
5. **标识符和错误。** 本批内部 UUID 路径格式无效返回 400；格式有效但不存在返回 404。未知命令返回清楚的 404，JSON 与 Node HTML 正文的差异不构成业务缺陷。协议级坏转义仍按 HTTP 解码错误处理。
6. **情报读模型和 no-op。** `focusAreas` 公开读模型始终为 `string[]`；合法旧数组超过写侧 12 项的读值不应截断。持久化 JSON null 可投影为空数组，非法旧对象不得裸返为错误类型，不在 GET 中偷偷改库。对语义上相同的空数组 PATCH，不隐式改业务版本、时间、操作者或审计；必要会话维护独立处理。

刚为缺陷兼容性添加的 `focusAreas` 额外 issue 和 HTML 404 修复已撤回；它们及旧审查意见保持历史原件，并由追加重分类覆盖当前结论。
